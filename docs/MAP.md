# Repository map

> Generated by `tools/map` from the README of each folder. Do not edit by hand.

## Folders

- `docs/`: What is in docs/; the block below is generated by .checks/docs_index.py.
- `docs/adr/`: Registros de decisión (ADR): una página por decisión, con contexto, decisión y consecuencias. Obligan a todos los agentes. Índice con estado en `docs/decisions.md`.
- `docs/reports/`: Informes de los agentes por ficha (`F-NNN/`), con formato fijo, consolidados por el arquitecto al cierre de cada ficha como trazabilidad.
- `docs/reports/F-000/`: Informes tal como los entregaron los agentes el 2026-11-04 (formato fijo de `docs/templates/`). Costos: verificador vuelta 1 USD 0,23; regresión de agentes USD 0,18; integrador USD 0,01 en total.
- `docs/specs/`: Fichas aprobadas por el dueño (F-NNN), en español, desde `TEMPLATE.md`; se publican a la base de conocimiento del dueño con `tools/publish-spec`.
- `docs/templates/`: Fixed formats of the agents' reports and of the approval summary the owner reads on the phone. Agents use them exactly.
- `experiments/`: Throwaway firmware that teaches or measures something and is never shipped: `blink/` (toolchain smoke test) and `hid-from-scratch/` (F-001: a hand-written HID keyboard with TinyUSB, no QMK).
- `experiments/blink/`: Toolchain smoke test for the Pico SDK container: `tools/build blink` must produce `build/blink/blink.uf2`. Not part of the product.
- `experiments/hid-from-scratch/`: A minimal USB HID keyboard written directly on the Pico SDK and TinyUSB, with the descriptors by hand, that logs how the host enumerates it and types the log out when BOOTSEL is pressed. Specified by spec F-001; empty until that spec runs. Build: `tools/build hid-from-scratch`.
- `firmware/`: The product firmware: a QMK external userspace. `keyboards/botonera/` defines the board (pins, matrix, encoder, OLED) and `keymaps/` the key maps; `qmk.lock` pins the exact QMK commit that `tools/build qmk` clones and compiles against. Empty until spec F-002.
- `firmware/keyboards/botonera/`: QMK keyboard definition (`info.json`, `config.h`, `rules.mk`, `botonera.c`). Created by spec F-002.
- `firmware/keymaps/default/`: The public example keymap, generated from `keymap.toml` by `tools/keymap` (spec F-002). Personal keymaps live outside the repository.
- `tests/acceptance/`: Acceptance tests written by the verifier from each spec, one folder per spec (`F-NNN/`). Host-side C tests build with the gcc of the build container; `device/` tests need the pad plugged into the server and skip otherwise.
- `tests/agents/`: Regresión de los agentes: una ficha de juguete con una ambigüedad y un error plantados, para comprobar que el ciclo los sigue detectando cuando el arquitecto cambia un agente.
- `tools/`: Process tooling kept by the architect: `launch-agent`, `integrator-brief`, `check-scope`, `publish-spec`, `map` and `build`, with their TypeScript in `lib/` (Node 24, no build step) and the host test helpers in `host/`.
- `tools/host/`: Host-side test helpers that run on the Linux server with the pad plugged in: read what the pad types through `evdev`, talk to it over Raw HID. Empty until specs F-001 and F-002.

## Agents

- `.claude/agents/integrator.md` (haiku): Makes the commits and pushes of Botonera at the end of each phase of the cycle (spec, tests, code, verification, review, close, process).
- `.claude/agents/programmer.md` (sonnet): Implements one approved spec of Botonera (docs/specs/F-NNN-*.md) in the branch and folder the architect names.
- `.claude/agents/reviewer.md` (haiku): Interprets the automated review of Botonera (scripts/review and .review/) only when needed.
- `.claude/agents/verifier.md` (sonnet): Verifies one spec of Botonera without the programmer's context.
